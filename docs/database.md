# Database Design

## Current Status

The database foundation is implemented with PostgreSQL 16 and psycopg 3. The schema
is defined in `database/schema.sql`; sample data and database integration tests live
in `database/seed.sql` and `database/tests/`.

## Connection

The backend reads `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD`.
Each connection uses a five-second timeout. The compose service exposes PostgreSQL
on host port `5433` and container port `5432`.

## Tables

### `users`

Stores local accounts and future SSO identity fields. UUIDs are generated by
PostgreSQL. Local accounts require a non-blank `password_hash`; SSO accounts use
`sso_id` and cannot have a local password. `email` is lowercase and unique.
`role` is one of `requester`, `support_engineer`, `manager`, or `admin`; `status` is
`active` or `inactive`. New administrator-provisioned local accounts have
`must_change_password = true`.

### `tickets`

Stores the ticket UUID, generated human-facing `ticket_number`, title, description,
JSONB `setup_snapshot`, priority, status, requester, assignee, due date, resolution,
timestamps, and `closed_at`. Priorities are lowercase database values (`low`,
`medium`, `high`, `critical`); statuses are `New`, `Open`, `In Progress`, `Resolved`,
and `Closed`. Constraints require resolutions for `Resolved` and `Closed` tickets and
require `closed_at` exactly when status is `Closed`.

Tickets are retained for auditability. Foreign keys use `ON DELETE RESTRICT` where
removing a referenced user or ticket would destroy ownership history.

### `ticket_comments`

Stores immutable comments with `ticket_id`, `author_id`, `comment_text`, `comment_type`,
and `created_at`. Valid types are `public`, `internal`, and `system`; only system
comments may omit an author. The current API creates public comments and maps
`author_id`/`comment_text` to `user_id`/`comment` in JSON.

### `ticket_history`

Stores immutable status audit events. `TICKET_CREATED` records `NULL -> New`; later
`STATUS_CHANGED` rows require different old and new statuses and record `changed_by`.

### `attachments`

Stores metadata only: original and generated file names, relative storage path, MIME
type, size, ticket/comment relationship, uploader, and creation time. File bytes are
kept in controlled server storage. Composite foreign-key validation ensures a comment
attachment belongs to the same ticket. Upload and download routes are not implemented
yet.

## Integrity and Indexing

The schema enables `pgcrypto` for UUID generation and uses CHECK constraints for
credentials, roles, statuses, priorities, non-blank text, comment visibility, and
ticket lifecycle fields. Indexes cover common ticket status, ownership, assignment,
creation-time, comment, history, and attachment queries.

## Local Development

Start PostgreSQL with `docker compose up -d postgres`, apply the schema and seed data
as needed, then run the backend from its virtual environment. `GET /api/health`
verifies the database connection with `SELECT 1`.
